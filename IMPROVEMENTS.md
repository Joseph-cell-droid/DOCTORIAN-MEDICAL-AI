# Doctorian Medical AI - Improvements & Security Hardening Log

This document summarizes the comprehensive security hardening, clinical safety upgrades, Hugging Face Router integration, UI refinement, and architectural improvements implemented in **Doctorian Medical AI**.

---

## 1. Security & Key Sanitization
- **Repository Secrets Removal**:
  - Removed all exposed and hardcoded Gemini and Hugging Face API keys and bearer tokens from `README.md`, `.env.example`, and frontend source files.
  - Sanitized `.env.example` to only feature clean, unfilled placeholder values for developer configuration.
- **Dynamic Encryption Architecture**:
  - Replaced the hardcoded salt string (`"doctorian-shared-quantum-key-2026-secure-salt"`) in `src/api.ts` with dynamic, environment-driven resolution (`VITE_ENCRYPTION_KEY` or `ENCRYPTION_KEY`).
  - Safe fallback salt is generated dynamically in browser/runtime contexts rather than committed in source.
- **No Hardcoded API Keys**:
  - All Hugging Face and Gemini API calls strictly resolve credentials through `localStorage` (`doctorian_hf_token`, `doctorian_gemini_key`) or standard environment variables (`HF_TOKEN`, `VITE_HF_TOKEN`, `HUGGINGFACE_API_KEY`, `VITE_GEMINI_API_KEY`).

---

## 2. AI Clinical Safety Architecture (`src/services/aiService.ts`)
- **Prohibition of Dogmatic Single-Diagnosis Generation**:
  - Replaced legacy system prompts that forced single definitive answers.
  - Instituted an evidence-based clinical reasoning protocol grounded in the **World Health Organization (WHO)** standards and the **Uganda Clinical Guidelines (UCG)**.
- **Mandatory 8-Section Diagnostic Structure**:
  Every clinical consult generated by the AI strictly follows this structured framework:
  1. `• SUMMARY OF PRESENTED SYMPTOMS`
  2. `• MOST LIKELY DIAGNOSIS (with estimated confidence)`
  3. `• DIFFERENTIAL DIAGNOSES (2–4 alternatives with rationale)`
  4. `• RECOMMENDED NEXT STEPS / INVESTIGATIONS`
  5. `• SUPPORTIVE CARE & SELF-MANAGEMENT`
  6. `• MEDICATION SUGGESTIONS (only when indicated + must be prescribed by a licensed clinician)`
  7. `• RED FLAGS – SEEK CARE IMMEDIATELY IF...`
  8. `• DISCLAIMER: This is not a medical diagnosis. Please consult a qualified healthcare professional.`
- **Explicit Role Definition**:
  - Emphasized that Doctorian AI functions strictly as a diagnostic support and clinical decision-assist tool, never a substitute for an in-person licensed healthcare professional.

## 3. Hugging Face Inference Router Integration
- **OpenAI-Compatible Hugging Face Router**:
  - Integrated `https://router.huggingface.co/v1/chat/completions` as the primary inference engine.
  - Default Model: `nvidia/NVIDIA-Nemotron-3-Ultra-550B-A55B-BF16:deepinfra` (configurable via `HUGGINGFACE_MODEL`).
- **Flexible Token Retrieval (`callHuggingFaceChat`)**:
  - Prioritizes user-provided token in `localStorage` (`doctorian_hf_token`), followed by environment variables (`HF_TOKEN`, `VITE_HF_TOKEN`, `HUGGINGFACE_API_KEY`).
- **Graceful Fallback Hierarchy**:
  - When a Hugging Face token is provided, Doctorian attempts Hugging Face inference first.
  - If no HF token is available or if the HF request fails, it seamlessly falls back to Google Gemini models (`gemini-2.5-flash`), followed by verified offline clinical heuristics if offline.
- **Client & Server Modernization**:
  - Updated legacy Hugging Face model endpoints in `src/api.ts` to utilize the modern OpenAI-compatible router protocol.
